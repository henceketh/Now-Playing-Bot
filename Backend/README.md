# Spotify backend

Конфигурация и запуск описаны в [корневом README](../README.md). Устанавливайте зависимости из корня через `npm ci`; запускайте `npm run start:backend` или, находясь в `Backend/`, `npm start`.

| Маршрут | Ответ |
| --- | --- |
| `GET /login` | OAuth redirect с state и cookie на 10 минут |
| `GET /mazafakatospotik` | Прежнее имя `/login` |
| `GET /callback` | Проверка state, обмен code, сохранение токенов |
| `GET /currently-playing` | JSON трека, playback, optional lyrics; `?lyrics=false` пропускает тексты |
| `GET /download-current-song` | MP3 текущего трека; `?track_id=...` защищает от смены песни |

Без авторизации API возвращает `401`; без текущего трека скачивание возвращает `404`; при смене песни — `409`; переполнение загрузок — `503`; upstream rate limit — `429` с `Retry-After`, если он предоставлен. Остальные внешние ошибки возвращают `502` без credentials и полного объекта исключения.

`services/spotify.js` обновляет токен перед истечением срока и один раз повторяет playback после `401`. Refresh token сохраняется вместе с новым access token, включая ротацию. Client credentials grant здесь не нужен: playback относится к пользователю.

Поиск YouTube ограничен 10 секундами, yt-dlp — 90 секундами. Одновременно выполняются максимум две загрузки; subprocess получает массив аргументов без shell. У каждой загрузки свой временный каталог, который очищается после передачи либо ошибки.

Этот API предназначен для приватного доступа. У него один общий Spotify-аккаунт; не выставляйте его напрямую в интернет.
